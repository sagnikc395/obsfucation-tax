# slides

`obfuscation-tax.pptx` was generated by `build_deck.js`, and every figure on a slide
comes from `ANALYSIS.md` or `README.md`, which in turn trace to files in `results/`.
`build_deck.js` is not in the repo any more, so the deck is currently its own source of
truth: the comparison slide was written straight into `ppt/slides/` and registered with
`add_slide.py` from the pptx skill. Restore the generator before the next structural
change, or that slide will be lost the first time the deck is rebuilt.

## Rebuilding

`pptxgenjs` is the only dependency and it is not vendored here:

```sh
npm install pptxgenjs
node build_deck.js
```

The generator also applies the theme colours through `apply_theme.js` from the pptx
skill, since pptxgenjs cannot write theme colours itself. Without it the deck still
builds, but scheme colours fall back to Office's stock palette:

```sh
APPLY_THEME=/path/to/pptx/scripts/apply_theme.js node build_deck.js
```

## Checks worth rerunning after an edit

```sh
python scripts/office/validate.py obfuscation-tax.pptx   # from the pptx skill
uv run --with python-pptx python check_geometry.py obfuscation-tax.pptx
```

Visual QA needs LibreOffice to render the deck to images, which is not installed on
this machine. `check_geometry.py` stands in for it: shapes against the canvas and the
0.5 inch margin, estimated wrapped text height per box, and overlapping text frames.
Its glyph widths are averages, so a flagged box is worth a look rather than certainly
wrong, and it does not catch everything a render would.

## Structure

Three sections, six slides. Two of them are the method, since that is where this run's
result actually lives:

| Slide | What is on it |
| --- | --- |
| The question | Where it comes from, the tax defined, and the three outcomes written down in advance |
| Where this sits | The three papers against this run, by what each asks, its model and read-out, its data, and its detection and capability metrics. Metric names only, no values |
| Method, end to end | The six steps of the pipeline, the probe and steering specs, and the two gates |
| Preconditions and controls | What the gates returned, the five controls, the group means, and the prompt confound |
| The sweep | The table, the residual arithmetic behind the probe column, and the two-sided correction |
| What the run still supports | The defence result, the behavioural signal, the flip-set churn, and what a re-run needs |

Two layouts carry the deck: `CONTENT` for the three light slides and `TITLE_DARK` /
`STATEMENT_DARK` for the opener and the close. Cards, badges and stat callouts are
composed per slide on top of those.
